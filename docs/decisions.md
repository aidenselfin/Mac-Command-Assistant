- 2026-10-14 파일 정리 도구: 승인·Undo가 있는 `local__move_file`(이름 변경 포함),
  `local__copy_file`, `local__create_directory`를 추가한다. 요청별 노출과 코드의 작업 범위 검증을
  모두 적용한다. 이동은 같은 파일시스템의 일반 파일 하나(최대 50 MiB), 덮어쓰기·폴더 이동은
  거부한다. 목적지 폴더가 없으면 폴더 생성과 이동을 각각 승인받는다. 이동·폴더 생성 기록은
  기존 Undo SQLite에 별도 테이블로 저장하고 쓰기·삭제 기록과 시각 순서로 되돌린다.
  폴더 생성 Undo는 비어 있고 동일한 폴더일 때만 허용한다. 이동을 write+delete로 흉내 내지 않는다.
  기능 목록과 이번 요청의 실행 권한을 구분해서 안내하며, 존재하는 도구를 없다고 답하면
  한 번 교정한다. 승인된 작업 없이 이동·복사·폴더 생성을 완료했다고 답할 수 없다.

- 2026-10-14 dev_report 후속 수정: 질문 답변·검색 조건은 파일 후보 선택 후에도 보존한다.
  작업이 없는 단독 `다시`/`retry`/`again` 요청은 자유 입력 답변을 실제 요청으로 삼는다.
  이미 구체적인 작업이 있는 요청은 답변만으로 삭제 권한을 넓히지 않는다.
  날짜·회의록·보고서·메모·예산안 단서로 삭제 파일을 검색할 수 있으며, 후보가 하나여도
  사용자가 정확한 파일을 선택한 뒤 별도 삭제 승인을 받는다. 선택한 파일 하나만 삭제할 수 있다.
  직전 대화 기억만으로 대상을 지정하지 않은 삭제를 허용하지 않는 정책은 유지한다.

  (`tool_use_failed`: 질문 도구의 `options: []`, 9개짜리 `extensions`, 삭제 도구 `oneOf`의 `paths` 누락). 그래서
  ① 모델에 주는 도구 스키마에는 개수·길이 상한과 `oneOf`를 두지 않고 상한은 코드에서 적용한다(삭제는 공급자용 단순

  거부된 도구·스키마 위반만 남기고 모델 인자 원문·요청 내용은 남기지 않는다. 무조건 재시도·공급자 fallback은 추가하지 않는다.

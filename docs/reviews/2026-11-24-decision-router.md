# 처음 라우팅에 결정 모델 쓰기 검토 (2026-11-24)

사용자 피드백: "처음 라우팅에 결정(decision) 모델을 써 보면 좋겠다."
처음 라우팅 = 명령을 받았을 때 노출할 도구와 넣을 지침 블록을 정하는 단계. 가벼운 검토이고 구현은 하지 않았다.

## 지금 구조

- 지침 블록: `Planner.swift`의 `systemPrompt(_:)`가 노출 도구 이름만 보고 고른다(open·web·convert·search 블록, common·safety는 항상).
- 노출 도구: `Planner+Loop.swift`의 매 라운드에서 웹 저장·스냅샷 대기·URL 유무 같은 상태로만 좁힌다. 그 외엔 `state.tools` 전부(도구 상수 16개 안팎).
- 즉 라우팅은 이미 "코드 규칙 + 상태 기계"로 일부 있고, 첫 라운드는 사실상 전부 노출이다.

## 방식 비교

| 방식 | 추가 지연 | 비용 | 오분류 위험 | 복구 |
|---|---|---|---|---|
| (a) 작은 모델 1회 호출(gpt-oss-20b 등)로 {도구 묶음, 블록} 선택 | 왕복 1회(Groq 기준 대략 0.2~0.6초, 추정·미측정) | 입력 짧아 메인 호출의 수% | 중간. 모호한 한국어 명령에서 묶음을 틀릴 수 있음 | 필요 도구가 없으면 다음 라운드 전체 노출 → 라운드 1회 낭비 |
| (b) 규칙·키워드 라우터(URL·확장자·"열어/변환/찾아" 등) | 0 | 0 | 낮음~중간. 놓친 표현은 "전부"로 떨어지게 하면 안전 | 기본값이 전부 노출이라 복구가 따로 필요 없음 |
| (c) 지금처럼 전부 | 0 | 0 | 없음 | - |

## 기대 이득이 작은 이유

- 블록 빼기 실험(`2026-11-18-prompt-ablation.md`)에서 openBlock 외 블록은 빼도 점수가 잡음 범위였다. 블록을 덜 넣어 얻는 정확도 이득이 거의 없다.
- 반대로 openBlock은 빼면 1/12로 무너졌다. 라우터가 "열기"를 놓치면 큰 손해다. 즉 오분류 비용이 이득보다 비대칭으로 크다.
- 도구 16개 정도는 큰 모델이 고르기에 부담되는 수준이 아니다. 토큰 절약은 있으나 Groq에서 지연·비용 차이는 작다.
- 결정 모델 호출은 매 명령 첫머리에 왕복을 하나 더 얹는다. 지금 병목(라운드 수·되묻기)을 줄이지 않는다.

## 안전 조건 (어느 방식이든)

- 라우터 출력은 `state.tools`(allowlist 통과분)의 부분집합으로만 교집합한다. 이름이 목록에 없으면 무시하고 추가하지 않는다.
- Guard 위험 분류·승인·`allowed_directories` 검사는 라우터 뒤 단계 그대로. 라우터는 실행 권한에 관여하지 않는다.
- safetyBlock·commonBlock은 라우터와 무관하게 항상 넣는다.
- 결정 모델 출력이 깨지거나 시간 초과면 (c) 전부 노출로 떨어진다(실패 시 기존 동작).
- 결정 모델에는 사용자 원문만 넣고 도구 결과는 넣지 않는다(주입 경로를 늘리지 않음).

## 측정 설계 (실행하지 않음)

1. 스위치 하나(`SYMBIO_ROUTER=off|rules|model`)를 두고 결과 `versions`에 기록한다. 기본 off.
2. 기준: `symbio-dev eval --live --suite prompt-regression --repeat 3` 전체 노출 2회(잡음 폭 확인).
3. 비교: 같은 명령으로 rules·model 각각 2회. 과제당 3회 차이 1~2건은 근거로 쓰지 않는다(ablation 메모의 잡음 기준).
4. 함께 볼 값: 통과율, 첫 호출 지침 해시 변화 과제 수, 과제별 LLM 라운드 수·총 시간(timing), 첫 호출 입력 토큰, 라우터 오분류로 전체 재노출된 횟수.
5. 웹 과제가 묶음에 없으므로(ablation 메모) 웹 라우팅은 이 묶음으로 판단하지 않는다. 필요하면 웹 과제 몇 개를 먼저 추가.
6. 판정: 통과율이 잡음 범위 안이고 총 시간이 줄었을 때만 채택. 오분류 재노출이 5%를 넘으면 기각.

## 결론

- 가능 여부: 가능하다. 공급자 설정이 base_url·모델 지정을 이미 지원해 작은 모델 호출 한 번을 더하는 건 어렵지 않다.
- 기대 이득: 작다. 블록을 줄여도 점수가 안 오르고, 도구 수가 적어 선택 부담도 작다. 이득은 토큰 수 정도이고 왕복 추가로 상쇄된다.
- 추천: 지금은 결정 모델 라우터를 넣지 않는다. 대신 (b) 규칙 라우터를 "빼기만, 모르면 전부" 원칙으로 첫 라운드에만 시험하는 쪽을 추천한다.
  도구가 30개 이상으로 늘거나 로컬 소형 모델(Qwen 등)이 메인이 되어 지침 길이가 정확도를 떨어뜨릴 때 (a)를 다시 검토한다.

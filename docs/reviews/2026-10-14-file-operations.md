## 원인

최근 실행 `c35998f927c548bf9675a4c27112d012`은 영어안내문을 삭제연습 폴더로 옮기는 요청이었다.
모델 목록에는 이동 도구가 없었고, 삭제도 명시적인 삭제 요청에만 노출되어 빠져 있었다.
모델은 검색·목록·읽기 후 이동을 복사+삭제로 대신하려고 했고, 삭제 도구가 현재 목록에 없다는
사실을 앱 전체의 기능 부재로 설명했다. `삭제연습`은 폴더 이름이며 삭제 명령이 아니다.
다른 최근 실행에서는 실제 `local__delete_files` 호출과 승인 후 삭제 성공도 기록되어 있다.

## 변경

- 파일 이동·이름 변경, 파일 복사, 폴더 생성의 앱 내부 도구를 추가했다. 요청별 노출,
  RiskGuard 분류·인자 검증·일회용 승인·원본/목적지 표시·실행 전 재검증까지 연결한다.
- 검색에서 확정한 파일은 이동·복사 전에 내용을 읽을 필요가 없다. 원본이 다른 파일이거나
  목적지가 사용자 요청/답변에 없으면 거부한다. 웹·읽기 요청·부정 명령에서 실행할 수 없다.
- 모델에게 앱 기능과 현재 요청에 제공된 도구를 구분해 알려 준다. 존재하는 도구를 없다고
  주장하면 한 번 실제 도구 사용으로 교정하고, 실제 이동·복사·폴더 생성 없이 완료할 수 없다.
- 이동을 텍스트 쓰기·복사+삭제로 우회하지 못하도록 전용 도구를 사용한다.
- 폴더 생성을 승인한 뒤 이동을 거절하면, 앞서 생성한 폴더가 유지되고 Undo 가능함을 안내한다.
- 이동은 같은 파일시스템에서 hard link를 만든 뒤 원본 이름을 제거한다. 대상은 덮어쓰지 않고
  원본과 대상의 inode·내용 해시를 확인한다. 일반 파일 하나, 최대 50 MiB로 제한한다.
- 새 목적지 폴더는 별도 승인 후 생성한다. 이동·폴더 생성은 기존 Undo journal의 별도 테이블에
  실행 전에 기록하고, 쓰기·삭제와 함께 가장 최근 작업부터 되돌린다. 복사는 기존 create Undo를
  재사용한다. 취소 시 작업 스레드를 끝까지 기다리며, 부분 이동도 Undo로 회복할 수 있다.
- Undo는 원래 위치의 새 파일, 이동한 파일 변경, 부모 폴더 교체, 만든 폴더의 새 내용에 대해
  중단한다. 링크 경로는 차단하고 부모 디렉터리 fd를 고정한다.
- UI 테스트의 기본 Undo DB도 tmp_path로 격리했다. 사용자 자료의 기존 삭제는 되돌리거나
  커밋하지 않았고, 다른 세션의 미추적 파일은 제 변경에 포함하지 않았다.

## 검증·한계

최근 이동 문장을 scripted 모델로 재현해 검색→원본/목적지 승인→이동→Undo를 확인한다.
직접 이름 변경·바이너리 복사·폴더 생성 후 이동의 별도 승인·거절·취소·재승인·충돌·실패 주입을
회귀 테스트로 검증한다. 대화형 CLI와 실제 Tk 승인 버튼도 자동 테스트한다.

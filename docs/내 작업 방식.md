# 내 작업 방식
모든 지침(전역 CLAUDE.md, AGENTS.md, 훅, 스킬)은 이 문서를 기준으로 한다. 서로 어긋나면 이 문서가 맞다.

## 웹 패널
웹 패널 : 프로그래밍 순서를 따라가기 위한 웹사이트. symbio의 구조 / 워크트리 현황 / 개발 도구 등을 보여줌. 나의 프로그램에 대한 멘탈 모델을 담고 있음.
*나의 멘탈 모델은 세션(짧은 글 또는 그래프)과 웹 패널을 통해 구성됨. 세션에서 그때그때 한 작업에 대한 정보를 배움, 웹 패널에선 하나의 세션 밖 큰 관점에서의 정보를 배움(프로그램 구조, 워크트리 등)
- 새로운 기능이 정말 추가되었는지, 어떤 워크트리가 존재하고 작업 중인지, 과거 기능이 아직 있는지 확인하는 용도.
- 워크트리가 없는 환경 개선 작업도 "환경 개선" 칸에 진행 중·끝난 것으로 보임.
- Claude와 분리된 상시 화면. 한 화면에 최대한 모으고, 자주 안 보는 것만 아래로 내림.
- 새로 만든 기능은 색으로 강조하고(7일), 나머지는 회색으로 차분하게 둠.
- 세션은 패널 코드를 고치지 않고 기록 파일(작업 기록·구조 그림·개발 도구·변경 메모)만 갱신함.

## 작업의 종류
작업은 프로그램 개선과 환경 개선 두 가지로 나눔.
프로그램 개선은 symbio 프로그램에 오류를 해결하거나 새로운 기능을 추가하는 것을 말함. 환경 개선은 claude.md 수정 또는 개발 도구 만들기 등 AI가 프로그램 개선하는 것을 돕기 위한 작업임.

## 작업 순서
수정할 사항 -> 세션 만들기 -> "프로젝트 이해해" -> "~~ 작업 명령" -> AI가 워크트리 만듦 & 웹 패널에 추가 -> AI가 작업 -> 내가 피드백 & AI가 수정 반복 -> "메인에 병합해" -> AI가 메인에 병합 & 워크트리 삭제 & 웹 패널에서 워크트리 삭제됨 & 새롭게 추가한 기능일 시 프로그램 구조에도 추가됨.
** 만약 환경 개선 중 지침을 추가하는 등의 작업은 얽혀있는 코드를 수정하는 것이 아니므로 타 세션과 충돌 위험이 적음. 따라서 워크트리를 따로 만들지 않고 직접 메인에서 수정함. 다만 환경 개선 중 검토 도구를 만드는 등의 작업은 충돌 위험이 있어 기존처럼 워크트리를 만드는 방식으로 진행함.
- 메인에서 직접 고치려면 세션을 워크트리 없이 메인 폴더에서 연다. 워크트리로 열린 세션이면 그 브랜치에서 고치고 "메인에 병합해"로 합친다.
- git 밖 파일(전역 지침·작업 기록·패널 기록)은 어느 세션에서든 바로 고친다.
- 브랜치는 그 브랜치의 역할을 설명하는 이름을 가짐.
- 한 브랜치에 서로 다른 두 기능을 넣지 않음. 다른 기능은 새 세션·새 브랜치에서 함.
- 여러 작업을 여러 워크트리에서 동시에 병렬로 진행함.
- 하위 세션을 쓰면 나는 상위 세션하고만 대화하고, 상위 세션이 알맞은 하위 세션에 일을 맡김.
- 작은 수정은 가볍게, 큰 변경은 기획 -> 계획 -> 구현 순서. 버그는 원인을 확인한 뒤 고치고, 완료 보고 전에 실제 출력으로 검증함.

## 소통
- 답변·작업 결과·커밋 메시지는 한국어로 씀.
- 글은 짧게(한 줄 60자 이하, 그래프가 있으면 2줄·없으면 3줄). 표·목록·긴 문단은 싫어함.
- 구조 설명은 글보다 그림(구조 그림)을 좋아함. 작업 보고를 그림으로 그리는 건 원치 않음.
- 도구 호출 사이에 설명을 쓰지 않고, 진행은 작업 목록으로만 알림.
- 용어는 쉬운 말로. 커밋 용어·파일명 대신 "무엇을 하는 것인지"를 씀.

## 비용·자원
- 유료 API는 묻지 말고 필요하면 바로 쓰고, 쓴 뒤 한 줄로만 알림.
- 능력 점수(벤치마크·live 평가)는 웬만하면 재지 않음. 기존 기록을 먼저 읽고, 방향을 정할 때만 씀. 평소 검증은 무료 재생 평가.
- Claude·Codex 5시간 한도를 보고 여유 있는 쪽에 일을 더 맡김.
- 코드를 20줄 이상 바꾸면 Codex 검토를 한 번 돌리고, 끝내기 전에 전체 점검을 함.

## 실패 원인과 Claude Code 인수인계

### 1. 명확한 변환·삭제 요청을 텍스트 승인 질문으로 끝냄 — 우선순위 높음

`convert_approve` 2·3회차, `delete_pattern` 2·3회차, `delete_approve` 3회차에서
탐색 도구만 실행한 뒤 최종 답변으로 승인 질문을 했다. 각각 JSON 생성 2건, 일괄 삭제 2건,
단일 삭제 1건이 누락됐다. 실제 변경 도구 `local__convert_file`/`local__delete_files`는 호출되지 않았다.
`unexpected`는 삭제 대상 파일이 그대로 남았다는 뜻이며 과다 삭제가 아니다.

확인한 코드: `voice_action/planner.py`의 `_continue`는 도구 없는 비어 있지 않은 답변을
일부 읽기·웹 조건 검사 후 `Completed`로 반환한다(현재 약 1163행).
변경 도구를 호출해야 `_approval_required`가 실제 승인 상태를 만든다(약 1533행).
따라서 일반 텍스트 승인 질문은 EvalRunner의 `user.approve=[true]` 입력을 소비하지 못하고 종료한다.
운영에서도 앱의 승인·실행 단계로 진입하지 못하는 문제가 생길 수 있다.

먼저 평가할 lesson 후보 문장:

> 명확한 파일 변환·삭제 요청은 대상 경로를 확인한 뒤 해당 변경 도구를 호출한다.
> 사용자 승인은 앱이 도구 호출을 검증하면서 요청하므로, 최종 텍스트로 승인 질문을 대신하지 않는다.

이 문장은 제안이며 DB에 후보로 추가하거나 채택하지 않았다. 승인을 생략하거나 자동 승인하는
수정은 하지 않는다. 후보가 실패 과제의 실행 누락을 해결하는지 먼저 같은 16과제 × 3회로 비교한다.
효과가 부족하면 프롬프트·도구 설명을 검토하고, Planner 완료 조건 변경은 별도의 동작 수정으로 다룬다.

### 2. HTML 읽기에서 중복 도구 호출 후 한도 소진 — 우선순위 중간

`read_document_html` 2회차는 search → local read_document → filesystem read_text_file →
local read_document를 실행한 뒤 모델 호출 5회 한도에 도달해 `error`로 끝났다.
1회차도 5회, 3회차는 4회 호출로 통과해 한도에 가깝다. 다른 파일을 수정한 흔적은 없다.

이는 HTML 파서 예외가 확인된 결과가 아니다. 저장 결과에는 전체 도구 반환값·대화 경로가 없으므로
반복 읽기의 구체적 원인은 확정할 수 없다. 다음 작업에서는 `local__read_document`의 결과 형식과
모델에 전달되는 설명을 확인하고, 내용을 얻은 뒤 요약으로 종료하도록 하는 별도 후보를 검토한다.
단순히 호출 한도를 올려 실패를 가리는 방식은 우선하지 않는다.

현재 채택 규칙은 목표 과제 통과 횟수 +2 이상을 요구한다. HTML은 이미 2/3이므로 단독으로
3/3이 되어도 개선 +1에 그쳐 채택이 아니라 보류다. 이 경우 과제·반복 수와 판정 규칙을
사전에 명시해 재평가해야 한다.

프로젝트 소스는 수정하지 않았다. 촬영 자료는 `162707b`에 보존했다.
촬영 도중 다른 에이전트의 코드 수정이 병행되었으므로, 이 보고서를 특정 소스 커밋의

## 목적과 확인 방법

파일명이 불명확한 요청의 한글·영문 검색, 파일명→폴더→내용 탐색,
후보 과다 재질문, 번호 파일 묶음, 큰 파일 처리, 점수 평가와 원인 추정의 실제 화면을 남긴다.

기존 Tkinter GUI, 실제 Groq `openai/gpt-oss-120b`, 모델 호출 한도 10회를 사용했다.
재현용 자료와 피드백·Undo DB는 `/private/tmp/voice-action-screenshots`에 분리했다.
기존 사용자 문서와 프로젝트의 운영 피드백 DB를 촬영용 자료로 사용하지 않았다.
화면은 생성 이미지나 목업이 아니라 실제 실행 창의 캡처다.

## 점수 기반 원인 추정과 피드백 연결

S7의 실제 평가 run은 `3f55bb3a17714597a983253833bfb4b0`이다.
격리 피드백 DB에서 다음 값을 확인하고 원문 없이
[근거 JSON](2026-10-07-ui-search-rating-evidence.json)에 보존했다.

```json
{"score": 2, "tags": [], "hypotheses": ["partial_read"],
 "measured": {"model_calls": 2, "llm_ms": 5934}}
```

점수 입력 → 실행 기록에 기반한 코드의 원인 추정 → 기존 피드백 DB 저장까지 실제 확인했다.
원인 추정은 사실 확정이 아니다. `partial_read`는 부분 읽기가 저평가의 원인일 수 있다는 신호다.
사용자 원인 버튼의 존재는 확인했지만, 각 버튼의 저장·변경 동작을 모두 수동 확인하지는 않았다.

같은 원인·태그의 낮은 점수가 서로 다른 실행에서 반복되면 R7로 기존 분석 루프에 연결하는
코드와 관련 테스트를 확인했다. **R7의 실제 OpenRouter 분석 완료, 후보 lesson 생성,
채택 후 품질 개선은 이번 촬영에서 검증하지 않았다.** 점수만으로 프롬프트가 자동 변경된다는
근거로 이 화면을 사용하면 안 된다.

## 한계와 후속 확인 사항

- 큰 파일은 전체 분할 읽기·전체 요약이 아니라 앞부분을 제한적으로 읽고 안내한다.
  화면의 50,012자는 당시 구현이 표시한 값이며 정확한 원문 읽기 문자 수를 별도로 대조하지 않았다.
- 내용 검색은 지원하는 텍스트 파일의 앞 64 KiB를 대상으로 한다.
  큰 파일 뒷부분에만 있는 검색어, PDF·이미지 내용 검색을 검증한 결과가 아니다.
- 실제 모델 호출 중 HTTP 400을 관찰했다. 오류 화면은 최종 7장에서 제외했다.
  공급자 원문을 확보하지 않았으므로 이 건의 정확한 원인을 단정하지 않는다.
- 일부 실행에서 창 활성화·식별·촬영 영역 문제가 발생해 재촬영했다.
  다른 앱이 섞이거나 결과가 완성되지 않은 이미지는 최종 자료에 포함하지 않았다.
- 병행 수정이 끝난 고정 커밋에서 S1~S7을 다시 실행하고, 후보 선택 후 다른 파일을 읽지 않는지,
  재질문 조건이 다음 검색에 유지되는지, 원인 버튼을 바꿔도 최신 평가만 집계되는지 확인한다.
- 같은 원인의 낮은 점수를 별도 실행 두 번에 입력해 R7 감지·분석 완료·후보 저장을 실제 확인한다.
  품질 개선은 별도의 기준선/후보 비교 평가로 판단한다.

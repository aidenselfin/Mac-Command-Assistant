# 실제 프로그램 스크린샷

기존 Tkinter GUI와 실제 Groq 모델, 격리된 예제 자료를 사용했습니다. 프로젝트 소스는 수정하지 않았습니다.

| 파일 | 보여주는 기능 |
|---|---|
| 01-english-korean.png | 한글 미팅 노트 요청 → 영문 파일명 후보·선택 버튼 |
| 02-folder-metadata.png | 파일명에 없는 프로젝트 폴더 이름으로 탐색·읽기 |
| 03-content-search.png | 파일명에 없는 출장 주제를 문서 내용에서 탐색 |
| 04-many-candidates.png | 후보 9개 → 전체 나열 대신 폴더별 재질문 |
| 05-numbered-files.png | 번호만 다른 37개 → 범위 요약·최신 파일 버튼 |
| 06-large-file.png | 큰 파일 부분 읽기 안내와 1~5점 버튼 |
| 07-rating-cause.png | 실제 2점 선택과 아쉬운 점 선택 버튼 |

검색 엔진은 파일명(name) → 폴더 경로(path) → 텍스트 내용(content) 순으로 탐색합니다. 실행 기록에서 오로라 요청은 path, 해외전시회 요청은 content로 확인했습니다. 사진 자체에는 내부 검색 단계가 직접 표시되지 않습니다.

장문보고서에 실제 2점을 입력한 평가 기록에는 score=2, hypotheses=[partial_read], model_calls=2가 저장됐습니다. 원인 추정은 UI에 직접 표시되지 않습니다. 같은 원인·태그의 낮은 점수가 서로 다른 실행에서 반복되면 R7로 기존 분석 루프에 연결하는 코드가 있으며 관련 테스트로 확인했습니다. 이번 촬영에서 R7의 실제 OpenRouter 분석 완료 화면은 확보하지 못했습니다.

큰 파일은 전체 분할 요약이 아니라 앞부분 약 50,000자를 읽고 제한을 알립니다. 내용 검색도 텍스트 파일 앞 64 KiB를 대상으로 합니다.

실제 API 요청 중 HTTP 400이 한 번 발생했습니다. 그 오류 화면은 최종 스크린샷에서 제외했습니다.

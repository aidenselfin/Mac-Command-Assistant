

# 📄 PRD: 지능형 창/패널(Pane) 분할 인식 및 단축키 기반 포커스 제어 시스템

## 1. 프로젝트 목적 (Objective)
사용자가 지정된 단축키(`Ctrl + Cmd + K`)를 눌렀을 때, 화면에 떠 있는 서로 다른 애플리케이션 창뿐만 아니라 **단일 애플리케이션 내의 다중 창, 탭, 분할 패널(Split Panes)**까지 완벽하게 식별하여 노란색 테두리와 **알파벳 단축키(오버레이 태그)**로 시각화합니다. 사용자가 화면에 표시된 알파벳 단축키를 입력하면 **즉시 해당 창/패널이 선택(Focus)되며 오버레이가 사라집니다.** 이를 통해 마우스 없이 키보드만으로 화면 내 모든 논리적 작업 영역을 빠르고 정확하게 이동하는 것을 목표로 합니다.

## 2. 다루는 문제 (Problem Statement)
* **현재의 한계 (Intra-app 식별 불가 및 마우스 의존):** 현재 로직은 `pyobjc-framework-Cocoa` 등을 활용해 최상위 애플리케이션 객체(App level)만 인식하고 있습니다. 따라서 Chrome 브라우저 창이 2개 떠 있거나 분할되어 있어도 거대한 덩어리로 인식하며, 화면을 구별하더라도 실제 해당 창으로 이동하려면 결국 마우스를 써야 합니다.
* **인지적 오류:** 사용자는 눈으로 '두 개의 작업 공간'을 보고 있지만, 시스템은 이를 분리하여 타겟팅할 수 있는 '고유의 키값'을 부여하지 못합니다.

## 3. 선행 사례 분석 (Precedent Research)
이 문제를 성공적으로 해결한 상용/오픈소스 툴들은 다음과 같은 방식을 사용합니다.

* **Homerow & Shortcat:** Mac 전체 시스템을 제어하는 이 툴들은 Mac의 **Accessibility API(손쉬운 사용 API)**를 깊게 파고들어 UI 요소를 실시간 분석합니다. 앱 내부에 숨겨진 `AXWindow`, `AXSplitGroup` 같은 하위 요소들의 좌표를 재귀적으로 추적하여 각각 **누르기 쉬운 알파벳 태그**를 붙이고, 사용자가 해당 알파벳을 치면 클릭이나 포커스 이동을 수행합니다.
* **Vimium (브라우저 확장):** 웹 브라우저 내에서 화면 요소마다 태그를 붙이는 Vimium은 HTML의 DOM 트리를 분석합니다. Mac 데스크탑 환경에서는 Accessibility 트리가 이 DOM 트리의 역할을 대신합니다.

## 4. 핵심 요구 사항 (Core Requirements)

### 4.1. 동작 시나리오 (User Flow)
오버레이 엔진은 창의 상태에 따라 두 가지 모드로 나뉘어 동작합니다:
* **모드1:** 전체화면이 아닌 일반 윈도우 창을 대상으로 하며, 최상위 창 영역 자체를 타겟팅합니다.
* **모드2:** 전체화면(Full-Screen)으로 실행 중인 앱을 대상으로 하며, 창 내부의 분할된 패널들을 재귀적으로 식별하여 각각 단축키를 할당합니다.

1. 사용자가 `Ctrl + Cmd + K`를 누릅니다.
2. 시스템이 현재 화면 상태를 스캔하여 모든 앱의 내부 창/분할 패널 좌표를 추출합니다.
3. 추출된 개별 좌표마다 **노란색 테두리와 함께 고유한 알파벳 단축키(예: A, S, D, F 등 누르기 쉬운 키) 힌트 박스**가 렌더링됩니다.
4. **[창 이동 시]** 사용자가 화면에 뜬 특정 알파벳(예: `F`)을 키보드로 누릅니다.
5. 시스템이 즉시 해당 알파벳이 부여된 창/패널로 **포커스를 이동(활성화)**시키고, 모든 오버레이를 해제합니다.
6. **[토글 취소 시]** 알파벳을 누르지 않고 다시 `Ctrl + Cmd + K`를 누르면 포커스 이동 없이 모든 오버레이가 즉시 화면에서 사라집니다 (Toggle-Off).

### 4.2. 기술적 접근법 및 해결 로직 (Approach & Solution)
하나의 프로그램 내에 있는 여러 창을 완벽하게 구별하고 제어하려면, 데이터 수집 방식을 '앱 단위'에서 'Accessibility 트리 탐색 단위'로 고도화해야 합니다.

* **UI 트리 재귀 탐색 (Recursive Tree Parsing):** `pyobjc-framework-ApplicationServices`를 사용하여 `AXWindow`나 `AXSplitGroup` 요소들의 고유 좌표(Position)와 크기(Size) 데이터를 추출합니다.
* **타이핑 박스(텍스트 입력 영역) 자동 우선 식별:** `AXTextField`, `AXTextArea`, `AXComboBox`, `AXSearchField` 속성을 갖는 요소들을 탐색 대상에 추가합니다. 이들 타이핑 요소는 크기가 작더라도 필터링되지 않으며, 다른 패널과 겹치거나 부모 그룹에 종속될 때 **0순위로 우선 식별**되어 바로 타이핑 모드로 진입할 수 있게 합니다.
* **알파벳 동적 매핑 및 리스너 가로채기:** 추출된 요소 갯수만큼 누르기 쉬운 알파벳(홈 로우 위주)을 순차적으로 매핑합니다. 타이핑 박스 영역에는 시각적으로 `[T]` 심볼이 추가된 태그가 표시됩니다. 오버레이가 켜져 있는 동안에는 타이핑이 텍스트 입력이 아닌 **단축키 이벤트**로 동작하도록 입력을 가로채야(Intercept) 합니다.
* **Accessibility API 기반 포커스 제어:** 매핑된 알파벳 키가 입력되면, 해당 `AXUIElement` 객체에 대해 포커스 액션을 트리거하여 해당 창을 운영체제 최상단으로 끌어올리고 커서를 위치시킵니다. 텍스트 박스인 경우 클릭 액션이나 포커스 제어를 통해 즉시 타이핑이 가능한 상태가 됩니다.

## 5. 무결점 구현을 위한 상세 기술 명세 (Technical Specifications)

이 프로젝트를 오류 없이 구현하기 위해 개발 단계에서 다음 아키텍처와 로직을 엄격하게 준수해야 합니다.

### 5.1. 글로벌 단축키 리스너 및 이벤트 가로채기 (Toggle & Intercept)
* **상태 변수 관리:** `is_overlay_active = False` 전역 상태 변수를 통해 현재 시스템이 '단축키 입력 대기 모드'인지 관리합니다.
* **단축키 후킹 (Intercept):** 오버레이가 `True`로 활성화된 상태에서는, 사용자가 누르는 키보드 알파벳(A~Z) 입력이 현재 열려있는 워드 프로세서 등에 타이핑되지 않도록 이벤트를 소비(Consume)하고 포커스 제어 명령으로 라우팅해야 합니다.

### 5.2. Accessibility API 기반 트리 탐색 및 매핑 (Core Engine)
1. **탐색 로직:** `NSWorkspace`와 `AXUIElementCreateApplication`을 이용해 최상위 앱부터 `AXWindow`, `AXSplitGroup` 자식 노드까지 재귀적으로 파고들어 좌표를 추출합니다.
2. **단축키 풀(Pool) 할당:** 추출된 각 패널 객체를 배열에 담고, 키보드에서 누르기 쉬운 문자열 리스트(예: `['A', 'S', 'D', 'F', 'J', 'K', 'L', 'Q', 'W', 'E', ...]`)를 인덱스 순서대로 1:1 맵핑(Dictionary 형태)합니다.

### 5.3. 투명 오버레이 및 단축키 버튼 렌더링 (Rendering Lifecycle)
* **렌더링:** Python의 GUI 라이브러리(`PyQt5`, `Tkinter` 등)를 사용하여 테두리만 있고 내부는 투명한 창을 생성합니다. 이때 각 테두리의 **좌측 상단**에 [5.2]에서 할당된 알파벳 텍스트를 담은 버튼 모양의 라벨(Label)을 함께 그립니다.
* **메모리 해제:** 단축키를 통해 창이 성공적으로 선택되거나, 토글-오프 명령이 들어오면 배열에 저장된 오버레이 윈도우 객체를 일괄 `destroy()` 하여 화면에서 제거합니다.

### 5.4. 창 포커스 및 활성화 로직 (Focus Management)
* 사용자가 특정 알파벳(예: 'S')을 누르면, 딕셔너리에서 'S' 키와 연결된 `AXUIElement` 객체와 해당 앱의 `PID`를 찾습니다.
* 먼저 `NSRunningApplication.activateWithOptions_` 등을 이용해 해당 앱 자체를 화면 최상단으로 올립니다(Raise).
* 이후 해당 `AXUIElement`에 대해 `kAXFocusedAttribute` 값을 `True`로 설정하거나 `kAXRaiseAction`을 실행하여, 시스템 포커스가 정확히 해당 분할 창(Pane)으로 이동하도록 제어합니다.

## 6. 요구사항 정의 (MoSCoW 우선순위)

* **Must Have (필수 구현)**
    * `Ctrl + Cmd + K` 단축키를 통한 오버레이 켜기/끄기 (Toggle) 로직 완벽 구현.
    * 앱의 윈도우 상태에 따라 **모드1**과 **모드2**를 자동으로 구분하고, 단일 앱 내에서 분리된 여러 개의 `AXWindow`나 분할 화면을 식별하여 각각 고유한 **알파벳 단축키**와 테두리를 할당하고 렌더링한다.
    * 오버레이 상태에서 **알파벳 키를 입력하면 해당 창(모드1) 또는 내부 패널(모드2)로 시스템 포커스(Focus)가 즉시 이동**하고 오버레이가 종료된다.
    * **Should Have (권장 구현)**
    * 가려져 있거나 최소화되어 사용자 눈에 보이지 않는 창/패널은 탐색 및 단축키 할당 대상에서 제외한다.
    * 오버레이가 켜져 있을 때 누르는 알파벳은 기존 화면에 텍스트로 타이핑되지 않도록 키 이벤트를 가로챈다.
    * **타이핑 영역 매직 타겟팅:** 화면 내에 입력 가능한 텍스트 박스(TextField, TextArea 등)가 존재하면, 해당 영역은 다른 큰 부모 컨테이너에 먹히지 않고 무조건 태그가 할당되어 사용자가 단축키로 타이핑 상태에 바로 진입할 수 있도록 유도한다.
* **Could Have (선택 구현)**
    * 앱 간의 구별을 더 명확히 하기 위해 애플리케이션 간 테두리/단축키 태그의 색상 미세 조정 (예: 활성 앱은 짙은 노란색, 비활성 앱은 연한 노란색).
* **Won't Have (이번 페이즈 제외)**
    * 화면에 패널이 너무 많아 알파벳 단일 문자(A~Z) 갯수를 초과할 경우, 2글자 조합(예: AA, AB)으로 확장하는 기능 (우선은 1글자 매핑에 집중).
    * 앱 내부의 아주 작은 버튼 단위까지 태그를 그리는 작업 (현재는 '창'과 '패널' 단위에만 집중).

## 7. 초정밀 UI/UX 디자인 및 렌더링 상세 명세 (Design Specifications)

본 시스템은 시각적 힌트가 화면을 덮었을 때 발생하는 사용자의 눈 피로도(Eye Strain)와 인지적 부하를 최소화하기 위해, 픽셀(px) 단위의 정교한 렌더링 규칙을 엄격하게 준수합니다.

### 7.1. 오버레이 단축키 버튼 (힌트 박스) 시각 디자인 규칙
창의 테두리에 생성되는 작은 '알파벳 태그 버튼'의 정확한 디자인 수치입니다.

* **색상 팔레트 (Color Scheme)**
  * **배경색 (Background):** `#FFE600` (밝은 머스타드 옐로우). 기존 순색 노란색(#FFFF00)이 주는 눈부심을 줄이면서도 대비를 극대화한 색상입니다.
  * **텍스트 색상 (Text):** `#1A1A1A` (다크 차콜). 완전한 검은색(#000000)보다 눈의 피로도가 덜하며 노란색 배경과 최고의 가독성을 냅니다.
  * **그림자 (Drop Shadow):** 태그가 배경 이미지에 묻히지 않도록 박스 하단에 약간의 그림자를 줍니다. (예: `rgba(0, 0, 0, 0.25)` 투명도의 그림자 `y축 2px`, `블러 4px`)
* **타이포그래피 (Typography)**
  * **폰트 (Font-Family):** `Menlo`, `Monaco` 또는 `SF Mono` 같은 **고정폭(Monospace) 폰트**를 강제합니다. (알파벳의 너비가 일정해야 눈에 빠르게 들어옵니다.)
  * **크기 및 굵기:** `14px`, `Bold` (테두리에 붙기 때문에 기존보다 살짝 키워서 시인성 확보).
  * **자간 (Letter-spacing):** `0.5px`
* **형태 및 여백 (Shape & Spacing)**
  * **내부 여백 (Padding):** 상하 `4px`, 좌우 `8px` (버튼처럼 누르기 쉬워 보이는 볼륨감).
  * **모서리 둥글기 (Border-Radius):** `4px` (부드러운 사각형 형태).

### 7.2. 단축키 버튼 배치 및 정렬 규칙 (Positioning & Offset)
단축키 태그가 창의 중요 콘텐츠나 탭 이름을 덮어버리지 않도록 세밀하게 배치해야 합니다.

* **기본 기준점:** 대상 UI 요소(창/패널)의 **좌측 상단 모서리 (Top-Left)**를 기준으로 렌더링합니다.
* **미세 오프셋 (Offset 조정):**
  * 테두리 선의 시작점인 (0, 0)에서 **X축으로 +8px**, **Y축으로 +8px** 만큼 창 안쪽으로 살짝 여백을 두고 배치합니다.
  * 이렇게 하면 테두리와 태그가 시각적으로 안정감 있게 결합되어 보입니다.
* **Z-Index:** 모든 오버레이 테두리와 태그 객체는 운영체제 최상단 계층(Always on Top)을 유지해야 합니다.

### 7.3. 패널/창 분할 경계선(Bounding Box) 시각 디자인
단일 앱 내에서 분할된 여러 창(`AXWindow` 또는 `AXSplitGroup`)을 구별하기 위한 전체 테두리 디자인입니다.

* **내부 채우기 (Fill):** 완전 투명 `rgba(0, 0, 0, 0)` (사용자의 작업을 가리면 안 됨).
* **테두리 선 (Stroke / Border):**
  * 두께 `3px`, 색상 `#FFE600`, 불투명도 `100%`.
* **테두리 위치 (Box-sizing):** 테두리가 실제 창 크기를 넘어가서 잘리지 않도록 테두리 선은 안쪽으로 그려져야 합니다 (Inside Stroke).

### 7.4. 애니메이션 및 전환 효과 (Transitions)
* **토글 등장/퇴장 (Fade In/Out):** `Ctrl + Cmd + K`를 눌렀을 때 0ms로 나타나는 것이 아니라, **150ms (0.15초)** 동안 투명도 0%에서 100%로 스무스하게 나타나는 `Ease-in-out` 페이드 애니메이션을 적용하여 고급스럽고 부드러운 사용감을 제공합니다.
